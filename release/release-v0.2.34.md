# Kun v0.2.34

v0.2.34 继续完善 Agent Graph、Design 工作区和 GUI/TUI 共享运行时。复杂任务现在可以在规划阶段得到人工修正，在执行阶段获得更清晰的监督与恢复；Design 支持用文件夹整理绘画；Windows 安装、TUI 附件和运行时协作也更加稳定。

### Agent Graph：规划修正与监督增强

- Graph 规划遇到需要人工确认或修正的候选方案时，会暂停当前回合并展示修正草稿；可以修改后继续，或取消本次规划。
- 活跃 Graph 的输入框会显示当前状态和操作提示；新消息可以排队等待 Graph 完成，也可以选择直接引导当前 Graph Lead。
- Graph 监督面板新增等待评审、主代理唤醒、子代理停滞、结果修复、冲突和恢复等状态与操作，便于处理需要人工介入的运行。
- 调度、Lead 评审、子代理报告和恢复流程增加幂等与存活检查，减少重复交付、监督停滞和运行状态不一致。

### Design：绘画与工作目录

- Design 工作区从“设计稿”统一为“绘画”，可以从主输入框创建带标题的绘画并直接打开专属画布和对话。
- 支持创建、重命名、删除和嵌套逻辑工作目录，并可移动绘画；目录索引和绘画归属会持久化保存，删除目录不会误删其中的绘画。
- 完善绘画历史清空、删除确认、标题回填、画布初始化和对话绑定，减少历史错位或误操作。

### GUI、TUI 与附件

- 旁支会话支持保留草稿附件和 Fast 模式；附件会通过共享 Runtime 正确上传并关联到对应工作区或线程。
- TUI、GUI 和后台任务的 Runtime 发现、数据读写协调、停止与恢复流程进一步加固，降低多个客户端同时使用时的冲突风险。
- TUI 启动时会检查 Node.js 版本，最低要求为 `22.19.0`；Windows 启动器会给出明确的版本提示。

### Windows 安装与存储

- Windows 安装器增加中断安装恢复和文件保留机制，能够安全处理旧版安装目录、未知文件和旧卸载器，失败时保留恢复目录与日志。
- 安装或更新后会自动整理 `kun` CLI 的 PATH，避免旧安装路径残留或出现重复入口。
- 新增 Windows 存储迁移能力（由构建开关控制）：可将 `.kun` 和 `.deepseekgui` 的实体数据迁移到其他本地 NTFS 磁盘，同时保持原有逻辑路径兼容；迁移包含预检、校验、健康检查和失败回滚。

### OpenConnector 调整

- 移除 OpenConnector 集成、Connector Center、相关 Runtime sidecar、设置项和本地化内容。
- Kun 仍保留现有的模型、工具、MCP、Extension 和共享 Runtime 能力；本次调整只影响 OpenConnector 相关功能。

### 文档与界面

- 更新 README 的产品说明、使用流程和 GUI/TUI/Graph/Design 介绍。
- 更新 Code、Write、Design 和自动化工作区截图，补充当前界面演示。
- 补充 Graph 引导、监督状态、Design 绘画和工作目录等多语言文案。

### 升级说明

- 从 `v0.2.33` 升级无需手动迁移普通会话、工作区或 Provider 配置。
- 使用 TUI 前请确保 Node.js 版本为 `22.19.0` 或更高。
- 依赖 OpenConnector 的用户需要注意：该集成已从本版本移除，相关入口和设置不再提供。
- Windows 存储迁移仅在启用对应构建开关的版本中可用；迁移前请关闭不希望被中断的活动任务，并使用固定的本地 NTFS 磁盘。
